# Mac LAN Collaboration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Prepare native Mac DSH collaboration using Ubuntu Qwen, retaining privacy confinement.
**Architecture:** Add portable pinned filesystem operations and local Docker command confinement; SSH forwards Qwen separately from sandbox commands.
**Tech Stack:** Node 22 ES modules, Python 3 POSIX dir_fd, Docker/Colima, node:test, existing DSH APIs.
**Spec:** docs/superpowers/specs/2026-09-13-mac-lan-design.md

## Global Constraints

- Preserve ordinary model behavior and auto/off/low/medium/high choices.
- Private source, output, diagnostics and local summaries never enter cloud requests.
- No unsandboxed fallback, remote Docker daemon, inherited credentials, or automatic image pull.
- Host-only sandboxBackend, dockerPath, dockerSocket, dockerImage and pythonPath cannot be edited by the UI settings API.
- Mac Qwen access uses a verified SSH tunnel; do not expose Ubuntu port 8000 to the LAN.
- No existing project files are newly authorized for cloud.

### Task 1: Portable confined files

Own src/workspace.js, src/confined-files.js, src/confined-files.py and test/confined-files.test.js. Expose createConfinedFiles({backend='auto',pythonPath=''}) returning asynchronous read(root,relative)->{data:Buffer,mode:number}, write(root,relative,data,mode), remove(root,relative), entries(root,relative='')->directory entries as needed. Keep the Linux descriptor approach or share the secure Python implementation only when selected. createWorkspace accepts pythonPath from first config argument and an optional filesystemBackend second-argument test seam. All path policy and commit checks remain. Use canonical os.tmpdir default. Add real-helper tests for read/write/remove, 2MiB size bound, nested creation, symlink and hardlink rejection, ancestor swap, FIFO rejection, unsafe relative paths and errno propagation. Run node --test test/confined-files.test.js test/workspace.test.js and commit owned files. Report test evidence in the ignored SDD workspace.

### Task 2: Docker command backend

Own src/sandbox.js, src/sandbox-docker.js, test/sandbox-docker.test.js. runSandbox(root,command,options) keeps existing interface and adds sandboxBackend, dockerPath, dockerSocket, dockerImage; auto picks bwrap/Linux and Docker/Darwin, unsupported platforms fail. Implement runDockerSandbox with local Unix endpoint forced on every CLI operation, empty temporary Docker config, fresh bounded environment, --pull=never, --network=none, --read-only, --cap-drop=ALL, --security-opt=no-new-privileges, process count/resource/output/time limits, user uid:gid, snapshot and readonly/writable exception mounts, isolated tmpfs/HOME. Generate unpredictable container name; ensure cancellation, error and completion remove the named container and descendants, including races during create/start. Validate all mount arguments and restrict image syntax; never invoke a shell on the host. Test executable argv/environment via fake CLI, local endpoint rejection, readonly mount exceptions, create/run failure, output limit, timeout, abort and container cleanup. Run existing workspace tests and new Docker tests; commit owned files and report.

### Task 3: Host integration and handoff

Own src/config.js, src/collaboration.js, test/collaboration.test.js, README.md, package.json, docs/mac-mini.md, scripts/check-mac-runtime.mjs. Pass host-only config through createWorkspace and runSandbox without allowing model/UI overrides. Bump 0.4.0. Provide Mac setup sequence: verified SSH forwarding, provider model/effort mapping, trusted provider id, native DSH installation, Python/Colima local prerequisites, pre-pull image and pin image ID, project grants, real container canary tests, real Qwen/online integration and UI checks. Store actual Ubuntu address and handoff prompt only outside published source. Run full tests/pack, source and security review. Publish if supported authenticated access works; install reviewed version on Ubuntu and preserve existing config/defaults.

### Task 4: Browser repair and release checks

Investigate config/read and configRequirements/read versus CUA policy availability, supported reset/reconnect, application diagnostics. Do not edit security decisions, bypass controls, or extract browser credentials. After legitimate repair, verify settings save/reload and five effort menu through CUA; synchronize complete reviewed tree to the user's existing fork and compare trees. If a service defect cannot be repaired within supported capabilities, preserve a concrete diagnostic report and give the Mac Codex handoff the local bundle as an authorized alternate source; do not claim UI/GitHub completion.
